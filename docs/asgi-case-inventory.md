# ASGI behavior and input inventory

> **Evidence path note:** Paths under `benchmarks/results/` identify local-only receipts excluded from Git. They are available only in a maintainer working copy when the referenced files are present; hosted artifacts are linked directly where available.

This page maps the project's declared ASGI behavior to its live input cases and
records known gaps. It is a focused compatibility inventory, not the official
ASGI conformance suite. The normative references are the [ASGI 3 callable
specification](https://asgi.readthedocs.io/en/latest/specs/main.html), [HTTP and
WebSocket sub-specification 2.5](https://asgi.readthedocs.io/en/latest/specs/www.html),
and [lifespan sub-specification 2.0](https://asgi.readthedocs.io/en/latest/specs/lifespan.html).

The indexed, input-only cases live in [`tests/parity/manifest.json`](https://github.com/appunni-m/uvicorn-rs/blob/main/tests/parity/manifest.json)
and [`tests/parity/inputs/`](https://github.com/appunni-m/uvicorn-rs/tree/main/tests/parity/inputs). They start a live
reference and target and compare wire-visible behavior. Cases marked
`verification: fault-contract` are target-only contracts; they are not counted
as oracle parity. The case IDs below name the current public input evidence.

## Known gaps and unsupported surface

- The ASGI HTTP 2.5 `http.response.start` contract says response header order
  must be preserved. The live interleaved input records a concrete H1/H2
  difference: the target groups fields by name while retaining same-name value
  order. RFC 9110 §5.3 says order across different field names is not
  significant to HTTP semantics, so this is an ASGI conformance deviation, not
  an HTTP semantic difference. The H3 probe reads fields through
  `http::HeaderMap` and cannot establish raw wire order. See [RFC 9110
  §5.3](https://www.rfc-editor.org/rfc/rfc9110.html#section-5.3), the [ASGI HTTP
  specification](https://asgi.readthedocs.io/en/latest/specs/www.html), and the
  focused receipt (`benchmarks/results/2026-10-12/psm2-response-header-order/README.md`).
- `http.response.trailers` and other optional response extensions are not
  implemented or advertised. An unknown `http.response.trailers` event is
  exercised by `http1.invalid-asgi-unknown-event-type`; this is not trailer
  support.
- WebSockets over HTTP/2 or HTTP/3, untested WSGI request/body/streaming and
  error cases, reload/watch, and worker
  supervision are not covered by this ASGI input inventory. Full Uvicorn CLI,
  API, and process compatibility is a separate versioned goal; see the
  [Uvicorn replacement status](uvicorn-compatibility.md).
- The official ASGI conformance suite and a complete HTTP security/framing
  corpus have not been run. Passing the indexed inputs is not full ASGI
  conformance.

See the [support matrix](support-matrix.md), [parity contract](parity.md), and
[unified coverage evidence](coverage.md) for current run identities and limits.
