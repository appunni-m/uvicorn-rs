# ASGI support matrix

The target is the ASGI 3 callable contract, HTTP/WebSocket sub-spec 2.5, and lifespan 2.0. The server implements HTTP/1.1, HTTP/2, and experimental HTTP/3. This matrix reports live cases run on CPython 3.12.13/macOS ARM64; it does not claim complete Uvicorn compatibility or full ASGI conformance. The version-pinned input-only parity run passed 19/19 cases on this local, dirty checkout; the latest [result](../benchmarks/results/full-rerun-2026-10-02T161854Z/asgi-parity.json) records per-input digests, reference dependencies, runner and app-fixture digests, extension digest, revision, and environment. The latest category rerun and its limits are recorded in [the feasibility report](feasibility.md) and the raw [run directory](../benchmarks/results/full-rerun-2026-10-02T161854Z/).

| Area | Status and live evidence | Limits |
|---|---|---|
| ASGI callable and Python loop | **Targeted cases pass.** Async apps, a synchronous callable returning an awaitable, execution on the loop that called `Server.serve()`, caller `ContextVar`, and standard event names carried by a `str` subclass are covered by [the HTTP probe](../scripts/probe_http.py) and HTTP/1.1 cases. Both asyncio and uvloop were measured. | CPython 3.12.13 is the only tested Python version. Other event loops and nested context/task combinations are unverified. |
| Context and exceptions | **Targeted cases pass.** Caller context crosses the boundary; an app exception produces HTTP 500 and retains the Python traceback. The exception benchmark checks 200 responses per sample at one in-flight request. | Exception benchmark samples are capped, short fixed-count runs. Exceptions at every ASGI message boundary and under concurrency are not covered. |
| HTTP/1.1 | **Implemented and exercised.** The probe checks request scope, upload, response status/body, exceptions, streaming, disconnect, and send-after-disconnect. The benchmark has 12 workloads and 144 rows: fixed response, 1 MiB response, 256×4 KiB and 128×512 B response chunks, 1 MiB upload, 64 KiB upload in 1 KiB pieces, slow reader, 32 headers, contextvars, synchronous callable, exception, and a `starlette-rs` route. | HTTP/1.0 is outside the target. Request-smuggling/security suites, malformed framing, and the complete HTTP edge-case inventory have not been run. |
| HTTP/2 | **Implemented; black-box scope and benchmark cases pass.** TLS ALPN and cleartext h2c prior knowledge report `http_version == "2"`. The 84-row benchmark covers protocol scope, fixed response, 1 MiB response, many response chunks, 1 MiB upload, 64 KiB upload in 1 KiB pieces, and a rate-paced slow reader. | h2c upgrade is unverified. Extended CONNECT WebSockets are unsupported. Large-scale stream-count, packet-loss, and flow-control stress cases are not covered. Hypercorn 0.18.0 is the same-protocol performance baseline because Uvicorn does not support HTTP/2. |
| HTTP/3 | **Experimental; current Rust-only 36-row matrix and targeted protocol/parity cases pass.** | The latest 66-row Hypercorn comparison aborted on four timeouts in a Hypercorn asyncio fixed-response case. Hypercorn 0.18.0 upload cases remain excluded because its upload path failed earlier correctness gates. Candidate-only data do not establish a cross-server speedup. H3 uses experimental Rust dependencies. Loss/recovery and broad interoperability remain open. WebSockets over HTTP/3 are unsupported. |
| Input-only protocol parity | **19/19 live source/target workflows passed.** The app is a synchronous callable that returns an awaitable; Uvicorn runs it with `--interface asgi3`, and Hypercorn uses explicit ASGI mode. H1, WebSockets, and lifecycle use Uvicorn 0.54.0; H2/H3 use Hypercorn 0.18.0 because Uvicorn has no matching server modes. Cases include H1/H2 progressive upload/response observations, H3 scope/stream bodies, disconnect, error, WebSocket, and graceful shutdown behavior. See the [suite contract](parity.md) and [current raw result](../benchmarks/results/full-rerun-2026-10-02T161854Z/asgi-parity.json). | One fixed app/case slice, CPython 3.12.13/macOS ARM64, dirty local target revision. It is not an official full ASGI suite, complete protocol security corpus, or Uvicorn CLI compatibility claim. |
| HTTP scope and multiplexing | **Targeted cases pass on H1, H2, and H3.** The negotiated protocol version is checked; H2 clients multiplex requests over four TLS connections, and H3 clients multiplex over up to four QUIC connections. Each request maps to a separate ASGI invocation. | Complete duplicate-header, pseudo-header, authority, raw-URI, and request-target case inventories have not been run. The H2/H3 clients and concurrency differ by transport; compare results within each protocol. |
| Request streaming | **Passes targeted cases.** The H1 probe confirms the app receives upload chunks incrementally and observes `http.disconnect` on an incomplete upload. H1/H2/H3 performance workloads consume 1 MiB uploads; H1 and H2 also measure 64 KiB uploads in 1 KiB pieces. | The incomplete-upload disconnect race was directly probed on H1 only. Body-size limits are not provided. Rust body chunks are copied into Python `bytes` when constructing ASGI events. |
| Response streaming and backpressure | **Passes targeted cases.** The H1 streaming probe checks ordered chunks and that response data arrives before the upload is closed. H1/H2/H3 benchmark cases include large and multi-chunk responses. H2/H3 slow readers are paced at 4 MiB/s; throughput and p50 latency are close to their same-protocol baselines. Immutable Python `bytes` response chunks are extracted as owner-backed Rust `Bytes`, avoiding a payload copy at that boundary. | The H1 slow-reader probe uses a 1 ms delay per client read event, so its rate is not directly comparable to the byte-paced H2/H3 cases. Each chunk still crosses the Python ASGI boundary; streamed H1 throughput remains substantially below Uvicorn's measured `uvloop + httptools` result. |
| WebSockets | **HTTP/1.1 Upgrade implemented.** The live probe covers handshake, subprotocol, text/binary echo, pre-accept denial, disconnect, and shutdown cancellation. The 36-row benchmark covers fresh handshakes, 32-byte text echo, and 64 KiB binary echo. | The handshake benchmark is a fixed 500 handshakes per sample at concurrency 1 to keep client ephemeral-port use bounded. Fragmentation, compression/extensions, malformed frames, and extended CONNECT are untested or unsupported. |
| Lifespan and shutdown | **Targeted cases pass.** Startup state, per-request shallow state copies, idle SIGTERM, and cancellation of a held request before lifespan shutdown are checked. Five repetitions per server were measured (20 lifecycle rows total). | Startup failure races and high-load shutdown are not covered. Stage deadlines with a zero timeout are not exhaustively tested. |
| Disconnect and cancellation | **Targeted cases pass.** Client disconnect produces `http.disconnect`; sending after disconnect raises `OSError`; SIGTERM cancels the remaining Python request task and lifespan shutdown completes. | Cancellation races under load and the same interrupted-transfer probe across H2/H3 are not covered. |
| CLI and deployment | **Documented subset implemented:** `module:app`, host, port, asyncio/uvloop, TLS files, graceful timeout, SIGINT, and SIGTERM. | No reload/watch, worker/process supervision, proxy headers, Uvicorn config files, Unix sockets, or general Uvicorn CLI compatibility. No package is published. |
| TLS and listeners | **Live TLS/ALPN cases pass.** TCP negotiates H2 or HTTP/1.1; QUIC negotiates H3. HTTPS/HTTP3 use the configured port. | Client certificate authentication, trusted proxy handling, configurable ALPN, and QUIC tuning are not provided. |
| Packaging and platform | **Local editable build and CLI work on macOS ARM64, CPython 3.12.13, Rust 1.98.1. CI is configured to build and smoke-test CPython 3.12.10 abi3 wheels on Linux x86-64, macOS ARM64, and Windows x86-64, and a source distribution on Linux.** | The new hosted matrix has not yet passed for a pushed commit. No public wheel/sdist, service-manager deployment validation, or published package exists. The declared Python `>=3.9` and Rust `1.83` minimums are not tested support ranges. See the [release candidate workflow](releases.md). |
| `starlette-rs` | **Optional integration passes.** One route from the separately installed framework works through the standard ASGI interface and is included in the HTTP/1.1 benchmark. | The server does not depend on, import, bundle, or install `starlette-rs`. One route is not framework-wide coverage. |
| Full ASGI conformance | **Not run.** The live probes below are focused black-box cases. | Passing these cases is not a claim that every ASGI 3, HTTP/WebSocket 2.5, or lifespan 2.0 requirement is covered. |
| Performance | **The latest run has correctness-gated samples for H1, H2, Rust-only H3, WebSockets, and lifecycle.** Raw rows include throughput, p50/p95/p99 latency, server/client CPU, and sampled RSS. | H1 and the H3 retry overlapped unrelated compiler/Python work; the H3 Hypercorn comparison failed its correctness gate. H1 Rust medians trailed Uvicorn on fixed and chunked responses and used more server CPU. H2/H3 use Hypercorn or candidate-only data; neither establishes a Uvicorn comparison. See [the feasibility report](feasibility.md) before drawing performance conclusions. |

## Live black-box probes

```sh
uv sync --python 3.12 --group benchmark --reinstall-package uvicorn-rs
uv run python scripts/probe_http.py
uv run python scripts/probe_http2.py
uv run python scripts/probe_streaming.py
uv run python scripts/probe_websocket.py
uv run python scripts/probe_cancellation.py
uv run python scripts/probe_lifespan.py
uv run python scripts/probe_starlette_rs.py  # requires a separate starlette-rs install
```
